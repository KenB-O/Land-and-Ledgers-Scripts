## V. Versioning and document-change protocol
1. Make modifications to Markdown or other editable master sources and export PDF snapshots; never write over frozen originals.
2. Use stable IDs for individual rules and historic observations; retain old-to-new ID mapping when adding/removing sections.
3. Each substantive change records reason, author/date, affected Canon/Technical IDs, evidence/source trail, status, regression impact and whether it actually changes gameplay.
4. An historical observation must include date, location, units, grading/scope, source quality and differentiation of claimed versus realized amounts.
5. No descriptive Business, occupation or settlement label can independently authorize an action.
6. Promote provisional Canon/Technical only after source-level semantic verification and resolution of conflicts; documentation approval is distinct from Unity implementation.
7. Retain complete older version artifacts as provenance, while ensuring only one named edition is active at any time.
